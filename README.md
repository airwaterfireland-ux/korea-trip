# 韓国旅行 2026 — 予約情報アプリ

2026/8/17〜8/26 のソウル旅行の予約情報を、スマホから素早く見るためのWebアプリです。
すべて静的ファイルなので **GitHub Pages に置けば完全無料**、韓国からも普通にアクセスできます。

起動時に4桁のパスコードを聞かれます（値はこのリポジトリには書きません。二人の間で直接共有してください）。

---

## 1. できること

| 機能 | 内容 |
|---|---|
| 日程 | 日付を選ぶとその日の予定がタイムライン表示。上の日付バーとカレンダーで移動。**各カードは折りたたみ式**で、初期状態は時刻・タイトル・場所だけ。タップで詳細とボタンが開く（右上の「すべて開く／すべて閉じる」で一括切替、開閉状態は端末に記憶） |
| 行きたい | 行きたいお店の専用タブ。上部の**ジャンルチップで絞り込み**、中は「日程が決まっている／日程前半／日程後半／時期は未定」でグループ分け。日程タブと同じく**カードは折りたたみ式**（右上に「すべて開く／すべて閉じる」）。**日付を決めても消えず**「日程決定 8/23(日) 18:00」バッジが付き、押すとその日の日程に飛ぶ |
| ホテル | Googleマップ／NAVERマップ／経路案内／電話／**Booking.comの予約詳細**／施設ページ／確認書PDF。**「🕒 時間を変更」でチェックイン・チェックアウト時刻を書き換えられます**（レイトチェックアウト等。2台で共有され、日程の並び順にも反映。「元の時間に戻す」で復帰） |
| フライト | 空港のフロアマップ・発着案内・アクセス、どこのカウンターへ行くかの案内、eチケットPDF |
| 書類 | 予約書類13点をアプリから直接表示（eチケット・電子入国申告書・Booking確認書・LuggAgent日本語訳/原本・ミートポイント写真/地図・ライナー券）。オフラインでも開けます |
| お店追加 | 右下の ＋ から店名・日時・場所を登録。2台の端末で共有される（下記の設定が必要） |
| オフライン | 一度開けばPDF込みでオフライン動作。ホーム画面に追加するとアプリのように使える |

## 2. GitHub Pages に公開する

> リポジトリは **Public** にする必要があります（Pages を無料で使うため）。
> URLを知っている人は誰でも見られます。パスコードと `noindex`（検索避け）は入れてありますが、
> 強固な鍵ではありません。URLは相手にだけ直接送ってください。

### 2-1. ローカルフォルダを GitHub につなぐ（初回だけ）

このフォルダは **すでに Git リポジトリになっています**（初回コミット済み）。
リモートを1回だけ登録すれば、以降は `./deploy.sh` だけで更新できます。

```bash
cd <このフォルダ>

# ① GitHub にリポジトリを作る（gh CLI が入っているので1コマンドで作れます）
gh repo create korea-trip --public --source=. --remote=origin --push

# ② GitHub Pages を有効化
gh api -X POST repos/airwaterfireland-ux/korea-trip/pages -f "source[branch]=main" -f "source[path]=/"
```

ブラウザで作りたい場合は https://github.com/new から Public で作り、次を実行：

```bash
git remote add origin https://github.com/airwaterfireland-ux/korea-trip.git
git push -u origin main
```

### 2-2. Pages を有効にする

リポジトリの **Settings → Pages** で

- Source: `Deploy from a branch`
- Branch: `main` / `/ (root)` → Save

1〜2分で `https://airwaterfireland-ux.github.io/korea-trip/` が公開されます。

### 2-3. 2回目以降の更新

**手動アップロードは不要です。** ファイルを直したら、フォルダで次を実行するだけ：

```bash
./deploy.sh "ホテルのメモを修正"
```

`deploy.sh` が以下をまとめてやります。

1. **GitHub の最新を取り込む**（スマホから追加したお店の予定を先に取り込む）
2. **`docs/` に変更があれば `sw.js` のバージョンを自動で上げる**
   （上げ忘れると、iPhoneに古いPDFがキャッシュされたままになります）
3. コミットして push
4. 公開URLを表示

push すると GitHub Pages が自動で再デプロイします。**ブランチを切らずに main で直接作業する前提なので、マージ作業は不要です。**

> **⚠️ `data/extras.json` だけは注意**
> このファイルは **アプリがスマホから GitHub 上で直接書き換えます**。
> ローカルでも同じファイルを編集して push しようとすると競合します。
> 原則 **お店の予定はアプリから追加し、ローカルでは触らない** のが安全です。
> 競合したときの対処は `deploy.sh` が画面に出します。

> **⚠️ OneDrive 配下にあることについて**
> このフォルダは OneDrive の中にあるので、`.git` フォルダも同期対象になります。
> 1人で1台から作業する分には問題ありませんが、複数PCで同時に触ると `.git` が壊れることがあります。
> 気になる場合は Finder で `korea-trip-app` を右クリック →「このデバイス上に常に保持する」にしておくか、
> OneDrive 外（例：`~/develop/korea-trip-app`）に移動してください。

### 2-4. iPhone のホーム画面に追加

1. Safari でURLを開く（Chrome ではなく **Safari**）
2. 4桁のパスコードを入力
3. 共有ボタン → **ホーム画面に追加**
4. アイコンから起動すると全画面のアプリとして動きます

このURLをもう一人にも送って、同じ手順をしてもらってください。

## 3. お店の予約を2人で共有できるようにする

追加した予定を **GitHub上の `data/extras.json` に直接書き込む** ことで共有します。
読み取りは設定不要ですが、書き込みには「アクセストークン」を各端末に1回だけ登録します。

### 3-1. トークンを作る（PCで1回だけ）

1. https://github.com/settings/personal-access-tokens/new を開く
   （Settings → Developer settings → Personal access tokens → **Fine-grained tokens**）
2. 次のように設定：
   - **Token name**: `korea-trip`
   - **Expiration**: 2026年9月末など、旅行後まで
   - **Repository access**: `Only select repositories` → `korea-trip` を選択
   - **Permissions → Repository permissions → Contents**: `Read and write`
3. 「Generate token」→ 表示された `github_pat_...` をコピー

> このトークンで**できるのは `korea-trip` リポジトリの読み書きだけ**です。
> 他のリポジトリやアカウント設定には一切触れません。旅行後は同じ画面から削除してください。

### 3-2. 各iPhoneに登録する

アプリの **設定タブ** を開き、

- GitHub ユーザー名 / リポジトリ名 … 自動で入っています（空なら手入力）
- アクセストークン … コピーしたものを貼り付け
- 「保存して接続テスト」→「接続できました」と出ればOK

もう一台のiPhoneでも同じトークンを貼り付ければ、**どちらから追加しても両方に反映**されます。

### 3-3. 使い方

- 右下の **＋** → 店名・日付・時刻・場所を入れて「保存」
- **日付を空のまま**保存すると「行きたい」タブに入ります（時期の目安として前半／後半を選べます）
- 保存すると即座にGitHubに書き込まれ、相手の端末は次にアプリを開いた時（またはアプリに戻った時）に反映されます
- カードの「編集」から修正・削除もできます
- 圏外やトークン未登録のときは端末内に保存され、**「未同期」** バッジが付きます。通信が戻ると自動で送信されます

## 4. パスコードを変える

パスコードを変えたい場合、Macのターミナルで新しい4桁のハッシュを出して差し替えます。

```bash
printf '1234' | shasum -a 256          # 1234 を好きな4桁に
```

出てきた64文字を `data/trip.json` の `meta.passcodeSha256` に貼り付けて再アップロード。

## 5. 内容を直したいとき

すべて `data/trip.json` に日本語でまとまっています。GitHub上で直接編集できます。

| 直したいもの | 場所 |
|---|---|
| フライトの時刻・空港案内 | `flights[]` の `time` / `guide` |
| ホテルの情報・注意書き | `stays[]`（チェックイン/アウト時刻は**アプリから変更するのが早い**） |
| 荷物配送・移動メモ | `events[]` |
| PDFの一覧 | `documents[]` |
| 緊急連絡先 | `emergency[]` |

直したら `./deploy.sh "何を直したか"` を実行すれば、1〜2分で反映されます。
GitHub 上で直接ファイルを編集してもかまいません（その場合、次にローカルで作業する前に `git pull` を忘れずに）。
`guide` や `notes` の中では `**太字**` が使えます。

## 7. ⚠️ 公開範囲についての注意

このリポジトリは **Public** です。アプリの利便性を優先して、以下をすべて含めています。

- パスポート番号・生年月日・電子入国申告書の発給番号
- 航空券の予約参照・eチケット番号
- ホテルの予約番号・暗証番号（＝Booking.comの予約を閲覧・キャンセルできる情報）
- 上記を含むPDF一式（`docs/`）

Pages側には `noindex` と `robots.txt` を入れてありますが、**GitHubのリポジトリ自体はコード検索の対象**です。
URLを知らなくても見つかる可能性があります。

### 旅行が終わったら

次のどちらかを必ず実行してください。

```bash
# A. リポジトリごと削除する（いちばん確実）
gh repo delete airwaterfireland-ux/korea-trip --yes

# B. Private にする（Pagesは無料プランだと止まります）
gh repo edit airwaterfireland-ux/korea-trip --visibility private --accept-visibility-change-consequences
```

あわせて、お店同期用に作った Personal Access Token も
https://github.com/settings/personal-access-tokens から削除してください。

## 8. ファイル構成

```
deploy.sh               更新して公開するスクリプト（./deploy.sh "メッセージ"）
index.html              画面の骨組み
app.css                 スタイル（ライト／ダーク自動切替）
app.js                  ロジック（表示・カレンダー・追加フォーム・GitHub同期）
sw.js                   オフライン用サービスワーカー
manifest.webmanifest    ホーム画面追加用
data/trip.json          確定した予約情報（すべて日本語）
data/extras.json        あとから追加するお店の予定（アプリが書き換える）
docs/                   予約書類13点（eチケット・入国申告書・Booking確認書・LuggAgent・ミートポイント等）
docs-src/*.html         日本語訳PDFの元データ。編集後 Chrome の「PDFに保存」で作り直せます
```
